# MTT Preflop Trainer — Web App Setup & Deploy

The trainer is a **Vite + React** app backed by **Supabase** (auth + database) and hosted
on **Vercel** — the same stack as Fantasy Poker. Range data comes from the Python
pipeline (see the root `README.md`): `python3 scripts/mtt.py build` writes
`web/public/ranges.json`, which the app fetches on load.

```
web/
├── public/ranges.json     # generated by scripts/mtt.py build (the range data)
├── src/
│   ├── App.jsx            # session + profile gate + tabs
│   ├── AuthPage.jsx       # email/password login
│   ├── OnboardingPage.jsx # pick a leaderboard name on first login
│   ├── TrainPage.jsx      # grouped scenario picker + quiz + records attempts
│   ├── AnalysisPage.jsx   # your accuracy, by pot type and exact spot
│   ├── LeaderboardPage.jsx# cross-user rankings
│   ├── poker.js           # hand notation, action labels, scenario grouping
│   ├── styles.js          # theme tokens (C = colors, F = fonts)
│   └── supabaseClient.js
└── supabase-schema.sql    # (in repo root) run once in Supabase
```

---

## Phase 1 — Supabase (database + auth)

1. Create a project at [supabase.com](https://supabase.com) (name it `mtt-trainer`, pick a
   region near you, save the DB password).
2. **SQL Editor → New query** → paste the entire contents of `supabase-schema.sql`
   (repo root) → **Run**. This creates `profiles` + `attempts`, row-level security, and
   the `leaderboard` / `leaderboard_by_pot` views.
3. **Settings → API** → copy the **Project URL** and the **anon / public** key.
4. **Authentication → Providers → Email** is on by default. For a friends app you can turn
   **off** "Confirm email" (Authentication → Providers → Email) so people can sign in
   immediately without a confirmation link. Leave it on if you prefer verified emails.

## Phase 2 — Run it locally

```bash
cd web
cp .env.local.example .env.local     # then paste your URL + anon key into it
npm install
npm run dev                          # http://localhost:5173
```

If you add or re-extract charts, regenerate the data and refresh:
```bash
python3 scripts/mtt.py build         # from repo root -> web/public/ranges.json
```

## Phase 3 — Deploy to Vercel

1. Push the repo to GitHub.
2. In Vercel: **New Project → import the repo**.
3. **Important — set Root Directory to `web`** (the Vite app lives in a subfolder).
   Framework preset auto-detects **Vite** (build `npm run build`, output `dist`).
4. **Environment Variables** → add:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
5. Deploy. You'll get `your-app.vercel.app`.

## Phase 4 — Custom domain

1. Vercel → your project → **Settings → Domains** → add your domain and follow the DNS
   instructions at your registrar.
2. **Supabase → Authentication → URL Configuration**: set **Site URL** to your final
   domain and add it (and the `*.vercel.app` URL) under **Redirect URLs**, so
   confirmation / password links point to the live site.

## How scoring, analysis and the leaderboard work

- Every answered hand inserts one row into `attempts` (the spot + your pick + correct?).
  RLS lets you read only your own attempts.
- **My Stats** aggregates your attempts into overall accuracy, accuracy by pot type, and a
  per-spot table you can sort by most misses / worst % / most played.
- **Leaderboard** reads the aggregate-only `leaderboard` and `leaderboard_by_pot` views
  (these expose counts + accuracy across all users, never individual hands). Rank by
  accuracy (min 20 spots to qualify) or by raw volume, filtered to any pot type.
